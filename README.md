This package provides GPU-accelerated versions of ERmod.
It includes an OpenACC version for NVIDIA GPUs and an OpenMP (target offload)
version for AMD GPUs.
The OpenACC version provides two programs, `erdst` and `slvfe`, and the OpenMP
version provides `erdst-openmp`, for GPU-accelerated solvation free energy
calculations based on the energy representation method.
For details on how to use ERmod and  information about the original code, please visit https://sourceforge.net/projects/ermod/.

ERmod (Energy Representation Module) is a program for calculating solvation free energies based on the energy representation method. It allows users to calculate the solvation free energies in arbitrary solvents, including inhomogeneous systems, and works in conjunction with state-of-the-art molecular simulation software, such as NAMD, GROMACS, and AMBER.

The `erdst` program (`erdst-openmp` in the OpenMP version) calculates the energy distribution functions required for energy representation theory from molecular simulation trajectories.
The `slvfe` program calculates solvation free energies from the energy distribution functions generated by erdst.

**Note:** `slvfe` also supports AMD GPUs (see its Configuration section
below), but pyslvfe (https://github.com/drmaruyama/pyslvfe) is
recommended over it for now, since `slvfe`'s AMD support is newer and
less tested than its original NVIDIA support.

## Directory Structure
- `erdst-common/` : source files shared by the OpenACC and OpenMP versions
- `erdst-openacc/` : `erdst` for NVIDIA GPUs (OpenACC)
- `erdst-openmp/` : `erdst-openmp` for AMD GPUs (OpenMP target offload)
- `slvfe/` : `slvfe` for NVIDIA GPUs (OpenACC)

The shared sources in `erdst-common/` are linked into `erdst-openacc/` or
`erdst-openmp/` automatically when `configure` is run, so no manual copying
is needed.

## Requirements
### OpenACC version (NVIDIA GPUs)
- NVIDIA HPC SDK (https://developer.nvidia.com/hpc-sdk)

### OpenMP version (AMD GPUs)
- ROCm with the `amdflang` Fortran compiler (tested with ROCm 7.2.0)
- hipFFT and hipfort (bundled with ROCm 7.x), for `erdst-openmp`
- hipSOLVER and hipfort (bundled with ROCm 7.x), for `slvfe`'s AMD support
- For multi-GPU execution, an MPI library built for `amdflang`

The OpenMP version has been tested on AMD Instinct MI300A (`gfx942`).
It uses hipFFT and therefore does not run on NVIDIA GPUs; use the OpenACC
version there.

## Typical Installation
This package uses Autotools for its build system. To compile the program,
1. `cd erdst-openacc`, `cd erdst-openmp`, or `cd slvfe`
2. Run `autoreconf -fiv`.
3. Run `configure` with the appropriate options (see below).
4. Run `make` to compile the program.

## Configuration
### erdst (OpenACC version)
In `erdst-openacc/`, for multi-GPU execution:
```
$ ./configure FC=nvfortran CC=nvc MPIFC=mpif90
```
or for single-GPU,
```
$ ./configure --disable-mpi FC=nvfortran CC=nvc
```

Single-precision calculations are enabled by default.
To enable double-precision calculations: 
```
$ ./configure --enable-double [other options]
```

If the configuration completes, run:
```
$ make
```
to start the compilation.

The OpenACC version supports only `nvfortran` as the compiler.

### erdst-openmp (OpenMP version)
Load the ROCm environment (and an MPI library built for `amdflang` if you
need multi-GPU execution) first, e.g. with your system's `module load`
commands.

In `erdst-openmp/`, for multi-GPU execution:
```
$ ./configure FC=amdflang CC=gcc MPIFC=mpif90 --with-offload-arch=gfx942
```
or for single-GPU,
```
$ ./configure --disable-mpi FC=amdflang CC=gcc --with-offload-arch=gfx942
```

`--with-offload-arch` specifies the target GPU architecture
(`gfx942` for MI300A/MI300X, `gfx90a` for MI210/MI250).
It defaults to `native`, which detects the GPU on the build machine; this
fails on login nodes without a GPU, so specify the architecture explicitly
in that case. You can check the architecture with `rocminfo | grep gfx` on
a GPU node.

Single-precision calculations are enabled by default.
To enable double-precision calculations: 
```
$ ./configure --enable-double [other options]
```

If the configuration completes, run:
```
$ make
```
to start the compilation.

The Fortran optimization level defaults to `-O2`. Higher levels (`-O3`)
are not recommended with current `amdflang`, which can drop GPU kernels
from the executable at `-O3`, causing a run-time error such as
`requested object was not found in the binary image`.

### slvfe
`slvfe` supports both NVIDIA and AMD GPUs, selected by `--with-gpu`
(auto-detected from `FC` if omitted) and currently supports single-GPU
execution only. See the note at the top of this file about pyslvfe.

For NVIDIA GPUs:
```
$ ./configure FC=nvfortran
```

For AMD GPUs, load the ROCm environment first (as for `erdst-openmp`
above), then:
```
$ ./configure FC=amdflang --with-offload-arch=gfx942
```
`--with-offload-arch` is the same option as for `erdst-openmp`; see the
note there about specifying it explicitly on login nodes without a GPU.

If the configuration completes successfully, run:
```
$ make
```
to start the compilation.

The configuration script supports `nvfortran` and `amdflang` as the
compiler.
